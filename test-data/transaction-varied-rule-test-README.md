# Varied Transaction Rule Test Dataset

Generated for the current merchant-focused scoring design. These are prototype testing rows, not production data.

## Files

- `transaction-varied-rule-test-cases.csv`: import this through the transaction import page.
- `transaction-varied-rule-test-cases.xlsx`: Excel version of the same import data, if generated.
- `transaction-varied-rule-test-expected-results.csv`: marking guide for the focus transaction in each test case.
- `transaction-varied-rule-test-expected-alert-queue.csv`: expected priority ordering by `priority_score DESC, txn_time DESC`.
- `transaction-varied-rule-test-terminals.sql`: optional prerequisite for the face-to-face outside-hours test.
- `transaction-varied-rule-test-priority-disabled.sql`: optional test-only setup for the disabled multiplier case.

## Before Importing

1. Confirm the demo merchants exist, especially `DEMO-FNB-LOW-001`, `DEMO-MONEY-HIGH-001`, `DEMO-BETTING-VERYHIGH-001`, and `DEMO-BAR-HOURS-001`.
2. If you want to test outside operating hours, apply `transaction-varied-rule-test-terminals.sql` first so `TERM-DEMO-BAR-001` exists.
3. Import into a clean test database or delete prior rows with the same `TXN-RS-` IDs in a test database only. Re-importing the same IDs will fail because transaction IDs are unique.

## Import Steps

1. Go to the transaction import page.
2. Upload `transaction-varied-rule-test-cases.csv` or `transaction-varied-rule-test-cases.xlsx`.
3. Preview the rows.
4. Process the import.
5. Compare the focus transaction IDs against `transaction-varied-rule-test-expected-results.csv`.

## Expected Formula

```
officialRiskScore = baseRuleScore + mccRiskPoints
priorityScore = officialRiskScore * priorityMultiplier
```

MCC points should be added once only, and only after at least one non-MCC suspicious rule triggers. Priority score is for queue ordering only.

## Where To Check Results

- Transactions page: confirm all imported transaction IDs appear and show the expected official risk score and risk level.
- Transaction risk score breakdown: confirm base rule score, MCC points, official score, priority multiplier and priority score match the expected-results file.
- Investigation Priority Queue: confirm higher priority scores appear above lower priority scores.
- Alert details page: confirm triggered rules and any suppressed/supporting evidence appear in the score breakdown.

## Queue Ordering Note

The expected queue file sorts by expected priority score and transaction timestamp for presentation clarity. The live alert queue sorts by `alerts.priority_score DESC, alerts.created_at DESC`. If you bulk import all rows at once, many alert `created_at` values may be nearly identical because the database creates alerts during import. For a strict created_at demonstration, submit selected rows individually a few minutes apart in a test database.

## Important Caveats

- Case 15 uses an invalid IP. If your current validation blocks invalid IP before risk scoring, test IP validation through direct backend/API testing instead of Excel import.
- Case 16 uses blank-space monitoring references because normal blank import cells are auto-generated by the controller before scoring.
- Case 20 requires temporarily disabling `use_priority_multiplier` for MCC 4829 in a test database. Do not run that SQL in production unless you intend to change the configuration.
- Daily count/value results assume the imported test date does not already contain many transactions for the same demo merchants. Existing historical data can change spike thresholds.
